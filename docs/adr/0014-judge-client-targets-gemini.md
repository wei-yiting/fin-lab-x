# ADR-0014: Judge client targets Gemini, exercising ADR-0007's provider escape hatch (2026-08-11)

**Decision**: The LLM-judge client (`_build_judge_client` in `scorer_registry.py`)
now targets Gemini's OpenAI-compatible endpoint
(`https://generativelanguage.googleapis.com/v1beta/openai/`) with
`GEMINI_API_KEY`, replacing the OpenAI endpoint/key ADR-0007 established. The
judge model is pinned to `gemini-3.6-flash`. Once pinned, the judge model
does not move when the agent model changes — the only exceptions are
provider deprecation or a future agent model landing back in the judge's
family — and any such swap requires re-running calibration and recording a
comparability break. Declared by DEV-146; TPR/TNR calibration against this
pin owned by DEV-123.

**Context**: the agent (`baseline` profile) moved to `openai:gpt-5-nano`;
the judge (`on_target_company`, formerly `response_relevance`) was `gpt-4o`
— same model family. An LLM judge scoring text generated by a same-family
model risks self-preference bias, threatening the independence the eval-rigor
zone assumes (design-envelope §4 (e): judge model recorded per run for
reproducibility — meaningless if the judge isn't independent of what it
scores). ADR-0007 anticipated exactly this: its **Re-evaluate if** clause
named "judge calls need multi-provider routing … picks a non-OpenAI judge"
as a trigger, and left a two-value escape hatch (`base_url`, key env var) at
the single client-construction site for this reason.

**How `gemini-3.6-flash` was reached — every earlier candidate failed a live
check, not a preference**:

1. The originally proposed `gemini-3.1-pro` **does not exist as a bare
   name** (live 404); the actual name, `gemini-3.1-pro-preview`, is a
   preview release, not GA.
2. Pinning a preview name carries documented, non-hypothetical churn risk:
   Google's migration guide records `gemini-3-flash-preview` being renamed
   to `gemini-3.5-flash` on GA, with API parameters changing in the same
   move (`thinking_budget` → `thinking_level`, `temperature`/`top_p`
   dropped).
3. The GA pro-tier alternative, `gemini-2.5-pro`, is **not callable on this
   account** (live 404, "no longer available to new users," pointing at
   Google's non-OpenAI-compatible Interactions API instead).
4. `gemini-3.6-flash` is the only candidate that is simultaneously GA (name
   won't be renamed out from under it), reachable on this account, and
   verified live to complete a binary-rubric tool call (`{"choice": "Y"}`
   via `tool_choice`) through the endpoint the judge client uses.

**This pin is provisional on one axis only**: it establishes independence
from self-preference bias. "How well does it agree with human judgment?" is
unproven — DEV-123 owns answering that via TPR/TNR before this model choice
is treated as final.

**Rejected — stay on OpenAI, switch model tier**: any OpenAI-family model
(e.g. `o4-mini`, `gpt-4.1`) still shares the agent's family; this solves
nothing on the independence axis this decision exists for.

**Rejected — route the new provider through the Braintrust gateway**:
ADR-0007's gateway rejections apply unchanged regardless of which provider
sits behind it — near-zero cache benefit (the rubric embeds `{{output}}`,
which differs every run), contradicts ADR-0006's local-by-default semantics,
and provider keys drift invisibly in Braintrust org settings.

**Why**: this is ADR-0007's own escape hatch firing on schedule — the
decision structure (explicit client construction, hardcoded endpoint,
fail-fast on missing key) is unchanged; only the two designated values
moved. The model choice itself came from elimination against live API
responses, not from a priori ranking — every rejected candidate failed a
concrete check (doesn't exist, will be renamed, isn't callable), not a
softer "less preferred" judgment.

**Re-evaluate if**: DEV-123's calibration finds `gemini-3.6-flash`'s
TPR/TNR unacceptable and a better candidate becomes reachable (swap and mark
comparability break); Gemini deprecates `gemini-3.6-flash`; or a future
agent model change lands the agent back in the Gemini family (re-collision).
