§1TL;DR

為什麼這個 PR 重要 舊版 streaming pipeline 只能處理 content 是 plain string 的 provider（OpenAI legacy）， Gemini / Anthropic 把 reasoning 塞進 content_blocks 之後完全沒被消化掉。 本 PR 把 StreamEventMapper 切到 LangChain v1 normalized content_blocks 為唯一 source of truth， 並把 reasoning text 經由全新的 ReasoningSegmenter 切句後，用 data-reasoning-status SSE event 推到 frontend， 搭配 ReasoningTraceCallback 把每次 LLM call 的完整 reasoning 寫進 Langfuse span metadata.reasoning。

三個面向同時動：

面向新增 / 修改對使用者 / operator 的影響
Streaming infra (Backend) ReasoningSegmenter new, ReasoningTraceCallback new, StreamEventMapper rewire to content_blocks, ReasoningStatus domain event + data-reasoning-status wire format multi-provider 都能正確 stream reasoning 並 trace 到 Langfuse
Reasoning UX (Frontend) useReasoningStatus hook new, ReasoningIndicator rewrite 為 idle / streaming / frozen 三模式, LiveStatusAnnouncer ARIA hybrid, Variant A CSS (vertical-slot 對齊) 使用者在 thinking moment 都看得到 ephemeral 狀態，含 stalled / STOPPED 提示
Provider & abort (Agents) v1–v5 切到 OpenAI gpt-5-mini reasoning on（曾短暫切到 Gemini 2.5 Flash）, _init_model 處理 provider-specific reasoning kwargs, _handle_abort_cleanup 寫 metadata.reasoning_tail_aborted + status="aborted" admin-configured reasoning capability；user abort 不再丟 segmenter tail

ReasoningSegmenter — sentence-boundary + 80-char CJK fallback

Gemini 中文 reasoning 幾乎不打 。 — 整段 thinking 可能一個 terminator 都沒有， buffer 會無限累積、frontend 一個字都看不到。所以這顆 segmenter 同時處理三種斷句訊號：

  • half-width .!? + 空白（避免切到 3.14，用 lookbehind 排除）
  • full-width CJK 標點 。！？ + 換行 \n — 不需要尾隨空白
  • 80-char soft-emit fallback — buffer 累積到 80 字還沒 terminator，整段 emit、buffer 清空（D26）

ReasoningTraceCallback — per-LLM-call Langfuse metadata

這顆 callback 訂閱 LangChain on_llm_end（chat-model 完成事件由它送，不是 on_chat_model_end）， 把每次 LLM call 的最終 AIMessage.content_blocks 內的 reasoning text join 起來，寫到對應的 Langfuse GENERATION span 上的 metadata.reasoning。

為什麼不用 update_current_generation() 原本 prototype 是叫 client.update_current_generation()，依賴 OTel context 找「當前 span」。 問題是 LangChain async dispatch 路徑下，callback frame 的 OTel context 不一定接得到 GENERATION span， 很多時候是 None 或上層 CHAIN，導致 update silently no-op。 改用 lookup-by-run_id — 直接從 handler._runs[run_id]（Langfuse 4.x 內部 dict）拿 GENERATION 物件，避開 OTel context 漂移。

class ReasoningTraceCallback(BaseCallbackHandler):

    def on_llm_end(self, response: LLMResult, *, run_id: UUID, **kwargs):
        try:

        except Exception:

def _lookup_generation_by_run_id(self, run_id: UUID) -> Any:
    """三層 fallback 防 Langfuse SDK 把 key 從 UUID 改成 str / hex."""
    runs = self._handler._runs
    observation = runs.get(run_id)             # 1. 當前契約 — UUID key
    if observation is not None:
        return observation
    observation = runs.get(str(run_id))         # 2. 字串化 drift
    if observation is not None:
        self._warn_drift_once("str(uuid)")
        return observation
    observation = runs.get(run_id.hex)          # 3. 無 dash hex drift
    if observation is not None:
        self._warn_drift_once("uuid.hex")
        return observation
    return None

_handle_abort_cleanup — D35 user-abort 後寫尾段

使用者按 Stop 時，LangChain 的 on_chat_model_end callback 不會 fire（in-flight LLM API call 被 cancel）， 所以 ReasoningTraceCallback 沒機會寫 metadata.reasoning。 這個 cleanup helper 直接從 handler._runs 找最近的 in-flight GENERATION，把 segmenter 殘留尾段寫到 metadata.reasoning_tail_aborted（注意：用不同的 key）， 並把 root CHAIN 標 status="aborted"。

def _handle_abort_cleanup(self, mapper, handler):
    """D35 abort cleanup — sync by design (sync code 不會被 CancelledError 打斷)."""
    from langfuse import LangfuseChain, LangfuseGeneration

    tail_segments: list[str] = []
    try:
        for event in mapper.finalize():
            if isinstance(event, ReasoningStatus):
                tail_segments.append(event.text)
    except Exception:
        logger.exception("mapper.finalize raised during abort cleanup")

    # 為什麼用 .values() 而不是 _lookup_generation_by_run_id：
    # 這裡 enumerate 整個 dict 的 value，對 key shape (UUID / str / hex) drift 免疫，
    # 只有 observation type drift 會壞 isinstance — 由 contract test 守住。
    in_flight_generation = None
    root_chain = None
    for observation in handler._runs.values():
        if isinstance(observation, LangfuseGeneration):
            in_flight_generation = observation
        elif isinstance(observation, LangfuseChain) and root_chain is None:
            root_chain = observation                    # parent_run_id is None 那個是 root

    if in_flight_generation is not None:
        in_flight_generation.update(
            metadata={"reasoning_tail_aborted": "\n".join(tail_segments)},
        )                                               # 空 buffer → 寫 "" 也算寫過
    if root_chain is not None:
        root_chain.update(metadata={"status": "aborted"})

    provider = _provider_prefix(name)

§5Frontend Walkthrough

useReasoningStatus — race-guarded ephemeral state

整顆 hook 解三個競態問題（D31）：

  1. Clear race：User 按「Clear」清空對話時，網路上可能還有 in-flight SSE 在 drain，這些 late event 不能再寫回 UI。用 clearedRef 鎖定。
  2. Finished ghost：finish / error 事件抵達後，backend 仍有可能 emit 一個 late data-reasoning-status（dev flag EMIT_LATE_REASONING 模擬此情境）。用 finishedRef 鎖定。
  3. Stalled 模式：10 秒沒收到新 reasoning chunk → 視覺切到 stalled（變淡 + 慢動畫），讓使用者知道「系統還活著只是慢」。

  const [stalled, setStalled] = useState(false);

  // 而不必等下一個 render
  const clearedRef = useRef(false);
  const finishedRef = useRef(false);
  const lastUpdateAtRef = useRef<number>(0);

  const handleData = useCallback((part: ReasoningStatusDataPart) => {
    if (clearedRef.current || finishedRef.current) return;   // 雙重 race guard

    switch (part.type) {
      case "data-reasoning-status": {
        if (typeof part.data?.text === "string") {
          setText(part.data.text);
          lastUpdateAtRef.current = Date.now();
          setStalled(false);
        }
        return;
      }
      case "finish":
      case "error": {
        setText(null);
        setStalled(false);
        finishedRef.current = true;     // 把開關鎖上，後續 late 事件全丟
        return;
      }
      default: return;
    }
  }, []);

  // 兩種 cleanup verb（語意不同）:
  //   hideReasoningStatus()  — 只清文字，不鎖 ref（下一個 LLM call 可以再用）
  //   clearReasoningStatus() — 清文字 + 鎖 clearedRef（user 顯式 clear）
  const hideReasoningStatus = useCallback(() => {
    setText(null);
    setStalled(false);
  }, []);

  const clearReasoningStatus = useCallback(() => {
    setText(null);
    setStalled(false);
    clearedRef.current = true;
  }, []);

  const resetForNewTurn = useCallback(() => {
    setText(null);
    setStalled(false);
    clearedRef.current = false;
    finishedRef.current = false;
  }, []);

  // stalled 偵測 — 只有有 text 時才開計時器，省 wakeup
  useEffect(() => {
    if (reasoningStatusText === null) return;
    const id = setInterval(() => {
      if (Date.now() - lastUpdateAtRef.current > STALLED_THRESHOLD_MS) {
        setStalled(true);
      }
    }, 1_000);
    return () => clearInterval(id);
  }, [reasoningStatusText]);

  return {
    reasoningStatusText, stalled, handleData,
    hideReasoningStatus, clearReasoningStatus, resetForNewTurn,
  };
}
Review point 注意 hideReasoningStatus vs clearReasoningStatus 的 語意分離 — Mid-turn 接到 text / tool 時用 hideReasoningStatus()（下一個 LLM call 還能再亮）； User 真的清對話才用 clearReasoningStatus()（鎖 ref，把整個 turn 的 late 事件全擋掉）。 混用會導致下一輪 LLM 的 reasoning 完全不顯示，是看起來不像 bug 的 bug。
