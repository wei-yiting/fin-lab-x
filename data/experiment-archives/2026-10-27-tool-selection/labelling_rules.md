# Tool Routing 標註：規則與已定案結果

定案結果的正式紀錄是 `tool_routing_labels.csv`；本檔只記規則。

## 規則

- **R1**：照題目真正需要的資訊來標。tool 拿不到的格子在備註寫「tool 不支援」。
- **R2**：Finnhub 報價只有在題目問到「當下價格或市場反應」時才必要；估值、期待值題目中，報價是被判斷的價格本身，標可接受；其他情況不必要。
- **R3**：「可接受」要能直接回答題目的某一部分；只是「跟答案一致、可以佐證」不算，標不必要。
- **R4**：
  - 問單一數字或趨勢（貴不貴、有沒有變差）→ Finnhub 財務（10-K 也能回答時，與 SEC 標成擇一必要）。
  - 問整體評估（財務體質、配息穩定性）→ SEC 必要；Finnhub 財務最多可接受。幾個比率不足以做整體判斷。
  - 問結構、曝險、原因 → SEC 必要；Finnhub 財務最多可接受。
- **R5**：題目明確限定看官方揭露時，Tavily 一律標不必要；只問「公司怎麼說」而未限定文件時，管理層在法說會的發言也算數，Tavily 可接受。
- **R6**：估值、市場期待相關的題目，Finnhub 財務必要，不與 SEC 擇一（10-K 沒有市價，算不出估值）。
- **Coverage gap 題**：需要的資料現有 tool 拿不到。不計入 routing 正確率，另外檢查：①回答有沒有說明證據不足；②有沒有反覆呼叫必定失敗的 tool。
- **Entity coverage**（多公司題）：除了 source recall，另外檢查每個「必要」來源是否涵蓋題目中的每一家公司（由 tool call 的 ticker 參數判斷，不需另外標註）。
- 標完 30 題之前，不看各 config 的實際行為。
