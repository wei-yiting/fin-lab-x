改了什麼

reasoning_segmenter.py

改了什麼

新檔。把 token-by-token reasoning 切成「完整句子」再 emit：half-width .!?+空白、CJK 。！？\n、80-char soft-emit fallback 三種訊號。

為什麼這樣設計

Gemini 中文 reasoning 幾乎不打 。 — 只靠標點斷句的話 buffer 無限累積、UI 一個字都看不到。80-char fallback 是給「沒有 terminator 的 provider」的保險絲（D26）。(?<!\d) lookbehind 防止切到 3.14。

帶走的 斷句／切 chunk 規則不要從「語言常識」正推，要從實際 provider 輸出反推 — 每家 LLM 的標點行為差異大到足以讓規則整組失效。永遠要有 size-based fallback。

event_mapper.py

改了什麼

從讀 chunk.content（plain string）改走 LangChain v1 normalized content_blocks；用 chunk.id transition 偵測 LLM-call boundary，flush 前一個 call 的 reasoning 尾段、reset segmenter。

為什麼這樣設計

Gemini 把 content 改成 list-of-blocks 後舊 mapper 直接吃癟。content_blocks 是三家 provider 都正規化成同一種 list 的介面 — 對它寫碼，一份 mapper 吃三家。id=None 視為 continuation，避免誤判 boundary。

帶走的 multi-provider 程式碼只碰 framework 的 normalized interface，不碰 provider raw payload。raw shape 是各家 SDK 的私有領土，隨版本漂移。

reasoning_trace_callback.py

改了什麼

新檔。訂閱 on_llm_end，把每次 LLM call 的最終 reasoning join 起來寫到 Langfuse GENERATION span 的 metadata.reasoning。

為什麼這樣設計

原 prototype 用 update_current_generation() 靠 OTel context 找「當前 span」，但 LangChain async dispatch 下 context 常接不到 GENERATION → silent no-op。改成 lookup-by-run_id（handler._runs），用明確的 key 對應取代 context 推斷。代價是依賴 Langfuse 4.x 私 API（hotspot 6.2，有 contract test 鎮守）。

帶走的 observability 寫入失敗常常是 silent 的 — 寧可依賴一個有 contract test 看守的私 API，也不要依賴一個會默默 no-op 的 context 機制。

agents/base.py · _handle_abort_cleanup

改了什麼

新 method。User 按 Stop 後，把 segmenter 殘留尾段寫到 metadata.reasoning_tail_aborted，root CHAIN 標 status="aborted"。

為什麼這樣設計

Abort 時 in-flight LLM call 被 cancel，on_chat_model_end 不會 fire — callback 路徑整條斷掉，只能由 agent 層補寫。整段是 sync code（sync 不會被 CancelledError 打斷）。用不同的 metadata key，讓「完整 reasoning」跟「abort 殘段」在 Langfuse 查詢時不會混在一起。

帶走的 設計 streaming pipeline 時，把「user abort」當一條一級路徑來畫 — 哪些 callback 不會 fire、誰負責收尾、partial data 寫到哪個 key，全部要明寫。

agents/base.py · _init_model

改了什麼

把 ModelConfig.reasoning + thinking_budget 翻譯成三家 SDK 各自認得的 kwargs（Gemini thinking_budget、Anthropic thinking={...}、OpenAI reasoning={...}）。

為什麼這樣設計

三家 kwarg 完全不同且各有地雷（Anthropic 要 budget≥1024 + temperature==1.0；OpenAI 少 summary="auto" 就不 emit reasoning）。集中在一個翻譯點，上層只看抽象的 reasoning: on/off/unsupported。"unsupported" 是給舊 model 的 escape hatch — 完全不傳 kwarg，避免 SDK reject 整個 init。

帶走的 provider 差異要壓在單一翻譯層，並且 enum 要預留「不支援」一格 — 不然每加一個老 model 就得在 call site 撒 if。

useReasoningStatus.ts

改了什麼

新 hook，持有 ephemeral reasoning text + stalled 狀態，內建三個 race guard：clear race（clearedRef）、finished ghost（finishedRef）、10s stalled 偵測。

為什麼這樣設計

TL;DR

為什麼這個 PR 存在

舊 streaming pipeline 假設 LLM 的 content 是 plain string — 只活在 OpenAI legacy 時代。Gemini / Anthropic 升級到 LangChain v1 後改成 content_blocks，把 reasoning 跟 text 拆成不同 block type，舊 mapper 完全沒消化。結果：跑 Gemini 的 agent 一個 reasoning sentence 都吐不到 frontend、Langfuse trace 上 metadata.reasoning 全空。本 PR 把整條 pipeline 切到 content_blocks 為唯一 source of truth，新增切句器 + 寫 trace 的 callback + 前端 ephemeral indicator，同時補上 user-abort 路徑的尾段 flush 與 distinct metadata key。

Before / After

Before — 舊 pipeline 在 Gemini/Anthropic 上的狀態
  • StreamEventMapper 直接讀 msg_chunk.content 假設是 plain string
  • Gemini 的 reasoning 跟 text 混在 list-of-blocks 裡 → mapper 跳過，0 個 reasoning event 到 frontend
  • Langfuse metadata.reasoning 沒人寫，每個 chat_model span 都是缺失的 key
  • User 按 Stop → segmenter buffer 內未斷句的尾段直接丟掉，trace 無紀錄
  • 前端只有一個固定 3-dot loading，沒 reasoning text、沒 stalled 提示、沒 STOPPED 標記
After — 多 provider + reasoning UX + 持久化 trace
  • StreamEventMapper dispatch on content_blocks[*].type：text / reasoning / tool_call_chunk 三條路
  • ReasoningSegmenter 切句（半形 .!? / 全形 。！？ / 80-char CJK fallback）→ ReasoningStatus domain event → data-reasoning-status SSE（帶 transient: true）
  • ReasoningTraceCallback.on_llm_end 每 chat_model call 寫 metadata.reasoning（5 種 value 狀態，always-write-key）
  • User abort → _handle_abort_cleanup 用 handler._runs.values() 找 in-flight GENERATION，寫 metadata.reasoning_tail_aborted + 根 chain metadata.status="aborted"
  • 前端 ReasoningIndicator 三 mode（idle / streaming / frozen）+ stalled 模式（10s 無 chunk 變淡）+ STOPPED 標記跨 turn 保留

Provider streams chunks (unchanged)

backend/agent_engine/streaming/reasoning_segmenter.py feed()

Reasoning text 是 stream chunk 形式（一個 chunk 可能 3 個字、可能整句），不能直接逐 chunk 推到前端 — 視覺會閃爆。ReasoningSegmenter 累積 buffer，碰到半形 .!? + 空白、全形 。！？、或 \n 切一句；如果累積 80 字還沒終結符（CJK fallback — Gemini 中文 reasoning 常常一句到底沒標點），soft-emit 整段並 reset。不能放 frontend — 不該把語言邏輯塞進 React。
