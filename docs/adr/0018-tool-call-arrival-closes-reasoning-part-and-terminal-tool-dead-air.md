# ADR-0018: Tool-call arrival closes the reasoning part and gates terminal-tool dead air (2026-08-04)

**Decision**: `StreamEventMapper` closes the currently open reasoning part the instant any tool-call representation appears in a chunk's `content_blocks` — `tool_call_chunk` (OpenAI/Anthropic normalized) or `tool_call` (Gemini normalized) — regardless of whether that tool call shares the reasoning block's own round. `useDeadAirPlaceholder` covers a third dead-air window (window C): every tool part in the turn has reached a terminal state (`output-available` / `output-error`) and nothing renderable has arrived since. Ruled via the DEV-109 grilling session (rulings 9 and 10).

**Context**: ADR-0015 (`reasoning-as-collapsed-transcript-chips.md` — main currently carries a second, unrelated file also numbered 0015; this ADR always means the chips one) assumed a same-round tool-call chunk should leave the reasoning chip open, so a tool card would still render below it once the args caught up. Manual BDD verification against real providers found the opposite on the project's default provider: the overlap lands on *every* round, not rarely, so the chip stayed open through the entire tool execution — a visible bug, not an edge case. The same verification pass found a second gap ADR-0015's two-window placeholder model didn't cover: once every tool part in a round reaches a terminal state, the wait for the next LLM call has no "thinking" affordance over it.

**Rejected — same-round exception (ADR-0015's original assumption, briefly shipped)**: keep the chip open while a tool call lands in the reasoning block's own round, closing only when the round itself changes. Matched an idealized single-provider timing model only; on the observed default provider the overlap is the common case, not the exception it was designed for.

**Rejected — provider-specific timing patches**: close early only for the provider observed to overlap, leaving others on round-based closing. Reintroduces the per-provider branching the `content_blocks` dispatch exists to avoid, and doesn't generalize — a provider not yet observed to overlap could start doing so without warning.

**Why**: both gaps trace to one root cause — ADR-0015's chip and placeholder model assumed provider timing that real multi-provider streaming doesn't match. The mapper closes on a single dispatch check (`block_type in ("tool_call", "tool_call_chunk")`) covering both normalized shapes with no provider-conditional branch; `backend/tests/streaming/test_event_mapper.py::TestReasoningPartBoundaries` exercises all three providers' shapes against it. The placeholder hook anchors windows B and C on the last *renderable* part rather than the raw last part, so an invisible trailing part — a reasoning block with no delta yet — can't end a window early or drop the placeholder while the screen still shows nothing new. Both land without provider-specific branching, in `backend/agent_engine/streaming/event_mapper.py` and `frontend/src/hooks/useDeadAirPlaceholder.ts` respectively. ADR-0015's "Consequences" line naming two dead-air windows is superseded by these three; the hooks' own README carries the current, mutable window-by-window description.

**Re-evaluate if**: a future provider's `content_blocks` normalization doesn't fit either `tool_call` or `tool_call_chunk` — extend the dispatch check's tuple, not a provider-conditional branch.
